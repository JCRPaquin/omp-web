# Shared design contract, version 3

Scope: source organization proposals only. No implementation/refactor now. Root package is one installable Bun CLI artifact (package.json:6-11), one lockfile, synchronized seven @oh-my-pi pins. Do not introduce separately released products as part of a structure change.

## Observed boundaries
- Browser is Solid and served by fleet edge; normal browser session path is POST/SSE -> fleet edge -> session daemon -> in-process agent SDK. Collab WS is a separate CLI/TUI-only surface. Managed clones have daemon-initiated authenticated callback up/down/bulk channels.
- fleet owns roster/process supervision, privileged workspace lifecycle and durable log mirror, not live agent state. session owns live AgentSession and JSONL truth. frontend has exactly one createStore (src/state.ts:229), action domain modules and stale-frame guards.
- Source is not strictly as leaf-only as docs/architecture.md:53-62 claims. fleet/server.ts:68 imports loopback policy from server/config; fleet/settings.ts:14-27 has SDK VALUE imports and reuses server/settings-model builders/coercion, not only types. Fleet composition imports runtime preparation/provider execution/verification. Do not equate zero agent state with zero static SDK imports. Lazy-loading changes are out of scope for these proposals.
- shared/protocol.ts:1-9 imports SDK types. A portable contract layer may remain SDK type-coupled without exposing SDK runtime code. shared/file-lock.ts and shared/testkit.ts are host/test-specific, unlike wire types and SSE helpers. Their new homes must be distinct.
- fleet/stats/index.ts owns a mountable read-only StatsApp. Its stored-source configuration has a type dependency on FleetLogStore (fleet/stats/config.ts:20-36); keep stats and stored sessions under fleet/history, not a nominal standalone package until that coupling has an actual separate consumer.
- server/quiesce-evidence.ts:8 imports runtime/export-sessions.ts for planSessionExport and verifyJsonlStructure. Runtime verification and fleet deletion also consume this module. Extract it unchanged into shared host session-files (A: shared/host/session-files.ts; B: src/platform/session-files.ts; C: packages/host-platform/src/session-files.ts), including its bounds, typed errors and relevant tests. This is archive traversal/structural evidence capability, not provider execution or lifecycle authority. Quiesce coordination stays session-owned; deletion gate stays fleet-owned; provider volume/store verification stays runtime-owned.
- Existing shared modules are not all portable: shared/provider-protocol.ts imports fs/path for parseProcStartTime/readProviderPidFile/matchProviderPidFile; shared/archive-manifest.ts imports crypto for computeExportId; shared/wake-materialize.ts imports fs/path/crypto for stored-file planning/emission. Split before relocating: portable types/constants/validators and typed error vocabulary stay contracts; provider process helpers -> runtime provider identity; computeExportId/canonical hashing -> host archive-id; planMaterializeFiles/emitMaterializeTransfer and their private host helpers -> fleet/history/materialize-transfer. Shared materialization request/record validation stays contracts. Existing shared/callback-protocol.ts imports SSE codec: split SSE/NDJSON stream codec functions into portable transport/callback, leaving shapes/constants/pure validators in contracts, so contracts do not depend on transport and workspace packages cannot form a contracts↔sse cycle.

## Dependency rules for every candidate
- Browser may import browser features, portable wire/domain types and SSE codec/constants, never host helpers, provider execution, SDK settings adapter or test support.
- CLI is the command dispatcher, allowed to call fleet/session entrypoints and update tools, not an owner of duplicated backend business logic. Preserve dynamic dispatch and stdout behavior.
- Fleet composition may depend on host runtime/provider helpers, contracts/transport, SDK-backed settings presentation, and fleet-owned features. Session composition depends on contracts/transport/host helpers and its SDK adapters, not fleet implementation.
- Runtime depends on provider/callback/archive contracts plus host capabilities; it must not import fleet lifecycle or browser implementation. Fleet constructs and injects runtime adapters.
- Shared SDK-backed settings presentation/coercion belongs in an explicitly host-only sdk-settings module. Session side effects stay session-owned; fleet persistence semantics stay fleet-owned. Keep common wire SettingsModel in contracts.
- Extract reusable numeric-host loopback classification from server/config into a small portable network-policy module used by session/fleet/other existing consumers. Do not move entire config parser into shared.
- Export only intentional module APIs. Avoid catch-all barrels and speculative interfaces. If public APIs change locations, migrate every caller without compatibility re-exports or deprecated paths. Current state facade may stay as a deliberate public boundary, not a legacy shim.

## Common cohesive splits
- Fleet HTTP composition: composition root wires fleet services; feature route adapters (projects/worktrees/clones/history) invoke existing services; browser edge pipe/replay/origin state remains together with its guards. Split route adapters/public projections from edge.ts, not generation/origin guards across competing owners.
- WorkspaceLifecycle remains THE single serializing/persisting create/ensure/stop/delete owner. Extract provider-specific operations and evidence gathering/verification helpers behind existing dependency seams. Never create independent create, stop and delete services with their own state.
- Session index.ts: extract HTTP authorization/download/command-admission adapters and SDK integration wiring; preserve command dedup + answer cache ownership, readiness, priming and resync order. Collab modules grouped together, unchanged transport.
- Frontend: one model/store construction; keep guarded frame ingress/reset/transport coordination together. Feature actions and components may move together. Extract types/pure reducers only where useful, not a store per feature. Preserve in-place live block mutation, DOMPurify markdown, CSS import order, localStorage keys, daemon-switch cleanup and dev state handle.
- Where B/C split the browser facade, model/core contains only types, the single store construction and store-local pure selectors. It imports neither feature actions nor transport. Move transport-dependent selectors such as hasLiveSession into the coordinator/selectors module; components import feature actions directly. Feature actions may import core and transport; transport may import core, never the coordinator. Guarded ingress/reset coordination imports domain handlers. Do not rebuild a cycle through an all-actions barrel.
- Frontend transcript tooling src/tx -> transcripts; similarly named fleet/stats remains server history/stats. src/usage/model-options.ts is model selection, not usage accounting. File-lock has a host-platform home; settings metadata is shared host SDK code, not backend cross-import.
- Consolidate history fixtures/generator ownership under fleet history tests; do not merge live SDK sessions, mirrored stored history and stats DB into one persistence authority.
- Concrete host/protocol split migration: runtime/verify-store follows host/archive-id for computeExportId; fleet/daemon-transport follows fleet/history/materialize-transfer for planMaterializeFiles/emitMaterializeTransfer and contracts for request validation; server/session-materialize keeps portable records/validators plus its own receiving/filesystem logic. Provider executable and process-identity test callers move to runtime/providers/identity as applicable; reference inventory establishes whether each existing exported helper actually has consumers before assigning it a public export. Callback stream codec callers in fleet/daemon-transport and server/fleet-callback move to transport/callback; all bounds/errors/auth/generation semantics unchanged. Move relevant owner tests and remove obsolete mixed modules/paths, with no compatibility re-exports.

## Test placement
- Pure/unit and owner-scoped integration tests co-locate as *.test.ts beside the implementation or under an owner __tests__/ folder for multiple-file features. Existing owner-co-located heavy tests remain there; heaviness alone does not require root placement.
- Only multi-product executable scenarios belong at root tests/system/ (fleet+daemon round trips, collaboration process scenarios, distribution/onboarding). Use one name tests/, not mixed test/ and tests/.
- Move current root test/ stats suite into fleet/history/stats/__tests__/ with its helpers and fixture generation; no duplicate legacy test/ path. Fixtures live beside their suite under fixtures/ (generated fixtures ignored), reusable helpers *.testkit.ts; new filesystem tests use tempDir().
- Split src/state.test.ts by observable behavior (transport/replay, chat streaming/history, attach/reset, fleet activity/auth) using an isolated state harness. This is not safe to do as filename-only churn because globals/module caches/timers require deliberate isolation. Do not newly pin tests of wording/source text/wiring.
- Test support has a separately named testing/ home, not part of production dependency exports. Keep commands rooted and physical-core worker policy/no live model convention.

## Valuable tests
1. Contract/transport boundaries: proto refusal, SSE arbitrary chunking/CRLF/replay window/backpressure, large-history chunking without partial visibility, command retries same-process at-most-once and restarted-process refusal, unicast answer isolation.
2. State transitions: reconnect/attach/session switch rejects old pending requests and stale frames; frontend in-place deltas and scroll/unread behavior; daemon idle/readiness; explicit clone session selection does not spuriously wake or create a fresh session.
3. Durable lifecycle: exclusive locks, atomic registry monotonic IDs, ack only after durable append, restart replay/offset gaps, byte-identical wake/materialization, failed deletion retains volume/logs; generation only after predecessor stop proof.
4. Security: path/symlink/download jail, secret-free public projections, callback enrollment/generation binding, bearer and CSRF/trusted-proxy boundaries, sandbox mount/env allowlists, dirty/stash/unpreserved Git deletion refusal. Use isolated behavior scenarios, not static source checks.
5. Actual user surfaces and shipped artifact: browser smoke for chat/roster/transcripts/settings and fleet-required notice; offline tarball install -> serve -> spawn -> update round trip; runtime-resource/image assets included and found; opt-in real bwrap/Kubernetes/proxy scenarios where prerequisites exist. Do not claim unavailable external environments are verified.

## Migration requirements
- Keep wire fields/version, URL routes, CLI verbs, persisted filenames and provider volume layouts unchanged; a source move never requires OMP_PROTO bump.
- Before every move identify import/symbol references, using LSP if operational. Here configured LSP could not start because node is missing, so bounded source imports supplied evidence instead.
- Actual shared/testkit.ts requires each importing test file to register afterAll(cleanupTempDirs) at its own top level. Keep that contract when moving the helper; automatic cleanup inside a shared helper module is not reliable across multi-file Bun runs.
- Update package scripts; cli/omp-web dispatch; scripts/dev; test fixture/runner/benchmark ownership; Vite root/index.html; TS/oxlint/oxfmt paths; build embedded-dist generate+finally-restore; runtime provider-exec/runtime image/resource relative paths; version/package lookup; release/preflight/onboarding probes; docs source/module links. Keep output dist/, dist-bundle/ and user-facing commands stable.
- Separate behavior extraction from mass moves into reviewable commits. Move each subsystem atomically with callers/tests; remove old paths. Run targeted owner tests + types, full suite for shared/daemon/edge, actual runtime/browser smoke, and distribution gate whenever entrypoints/build/runtime assets move. No extra tests merely to assert filenames.
- Contribution guide should gain a task-to-path map (wire method, roster action, provider, transcript endpoint, settings), allowed-dependency diagram and check command by scope, instead of forcing every contributor to start with the large engineering ledger.
